# Filtrado conservador de medios al servir Nuvio y Stremio

> Las cifras de 34 bundles y la mención de CineHax corresponden a la auditoría histórica citada. [Inventario vigente](providers.md); CineHax y TukiPlay fueron retirados posteriormente por petición. El filtro ahora también **conserva como inconclusos** los segmentos AES-128 con clave válida y bytes cifrados aunque el CDN anuncie `text/html`; sigue rechazando HTML legible y 403 confirmados (caso [VixSrc](revision-seis-sitios-2026.md)).

Cambio independiente en `src/core/media-filter.js`, integrado en `providerGuard` (`src/core/streams.js`): **los 34 bundles** usados por Nuvio y por el addon Stremio intentan descartar enlaces de HLS/MP4 *individuales* que muestran evidencia de no ser vídeo. No procede de código de CNCVerse: su [revisión](revision-cncverse-cloudstream.md) no identificó fuentes actuales reutilizables bajo Apache-2.0.

## Qué se prueba

- Se solicita la **URL del medio**, no la página de búsqueda ni el iframe. Para MP4 se pide `GET` con `Range` y se acepta `ftyp`; se rechazan HTML/JSON/imágenes y recursos vacíos. Para HLS se exige `#EXTM3U`, se siguen como máximo **tres variantes** por nivel (máximo dos niveles), se comprueba la clave AES-128 o la inicialización si está declarada y se prueban **hasta los dos primeros segmentos**. Un segmento MPEG-TS, fMP4, AAC o ID3 accesible sirve como prueba acotada; un HLS 200 con segmentos HTML 200 **no** basta.
- Si `Range` responde 401/403/404/410/416, el addon Node contrasta con **GET sin Range** mediante un lector que cancela el cuerpo tras los primeros bytes. Un 403 del catálogo no afecta al resultado. Si alguna variante/segmento es utilizable, se conserva el enlace; si los segmentos muestreados son todos inequívocamente inválidos, se descarta **esa URL**, no el proveedor.
- Se conservan los casos **inconclusos** (timeout, error de red, 429, 5xx, tamaño desconocido, otras variantes no verificadas, fuente sin firma reconocible). No se prometen imagen, audio, idioma, duración ni acceso desde otra IP. Los MP4 `.mkv`/`.webm` se dejan como antes; este filtro concierne únicamente a HLS y MP4.

## Seguridad y límites operativos

El presupuesto adicional máximo es **2,4 s por proveedor**, **dos sondas simultáneas** y **seis enlaces** revisados por llamada. Se repite un resultado negativo antes de ocultar la URL: un 403/HTML transitorio seguido de vídeo o de una respuesta incierta **no** basta. Las muestras de playlists se limitan a 64 KiB y las de fragmentos/MP4 a 2048 bytes **en Node**; la solicitud lleva `Range` y, si se ignora, el lector de Node cancela el resto. Se excluyen de las sondas URLs locales/privadas evidentes y redirects hacia esas direcciones; las cabeceras `Cookie`/`Authorization` no se reenvían a un host distinto tras un redirect. Esto no es un proxy público de reproducción ni una defensa completa frente a DNS rebinding en la fase de descubrimiento existente.

**Nuvio/QuickJS** expone `arrayBuffer()`, pero su puente nativo **recibe el cuerpo completo** antes de entregarlo al plugin. Para evitar que un host que ignore `Range` provoque la descarga de una película, se requiere primero un `HEAD` 200 con `Content-Length` conocido de **como máximo 128 KiB para cada URL**, incluidas playlists, inicializaciones y segmentos. Si `HEAD` no sirve, el cuerpo es grande o la longitud no se conoce, se **conserva** el candidato sin verificar; incluso con ese límite se depende de que el servidor anuncie correctamente el tamaño. No se hace GET sin Range para confirmar un 403 en QuickJS. Un MP4 grande normal, por tanto, no se verifica desde el plugin: el addon Node sí puede sondearlo por streaming.

**Rescate vía proxy en Stremio:** el proxy actual de scraping acumula las respuestas antes de pasarlas a `fetch`. El filtro se omite **solo dentro del contexto del proxy**, aislado con `AsyncLocalStorage`, para no descargar una película entera por accidente si un host ignora Range. Las fuentes rescatadas así siguen **sin validar** y pueden contener enlaces rotos; no se etiquetan como comprobadas. Tanto el addon directo como Nuvio sí utilizan el filtro. La caché existente del addon puede devolver enlaces que caducaron después de la sonda.

**Auditoría en Actions:** `scripts/media-audit.cjs` desactiva únicamente el filtro del runtime durante el descubrimiento, para registrar los enlaces *originales*. Después pasa hasta seis candidatos por el filtro y publica **solo cuántos/qué hosts** descartaría; la auditoría independiente sigue sondeando HLS/MP4 desde GitHub Actions **tres veces por web**. Solo se propone retirar un proveedor si **todos** sus medios encontrados dieron 403 en los tres intentos; una alternativa válida impide esa decisión. El filtro del runtime nunca cambia `manifest.json`, ni deshabilita la web por un único fallo del vídeo. Los fixtures de `tests/media-filter.test.cjs` y la integración en `tests/stremio.test.cjs` comprueban precisamente las distinciones entre HTML 200, `Range` 403, recurso de inicialización 403, alternativa sana, red indeterminada y limitaciones QuickJS/proxy.

### Resultado real tras corregir falsos positivos

[Actions 42305392461](https://github.com/noe359866-code/STREAMFLIX2/actions/runs/42305392461), commit `b3eaa0a`: **32 proveedores × 3 intentos**, 34 bundles y **106/106 pruebas**. El filtro descartó en **los tres intentos** el HLS Zilla con inicialización 403 de AnimeAV1 y los enlaces Nupload cuyos segmentos eran HTML 200 en **PelisflixHD y Repelis24**. Conservó los otros HLS/MP4 de AnimeAV1: la auditoría independiente comprobó MPEG-TS y `ftyp` 206 en los tres intentos. Solo AnimeAV1, CineHax, Embed69 y VideoAPI aportaron alguna muestra válida en esta red; los otros **28 quedaron no concluyentes** y **no hay propuestas de retirada de proveedores**.

En una [primera pasada 42304670487](https://github.com/noe359866-code/STREAMFLIX2/actions/runs/42304670487), una sonda única ocultó **una vez** otro HLS de AnimeAV1 que una comprobación posterior encontró válido; por eso ahora **se confirma el resultado negativo con una segunda petición**. En la última pasada ese enlace se conservó **3/3**. Los anuncios PNG de CineHax **no se descartaron en la ventana temporal del filtro**, aunque la auditoría detectó sus bytes no válidos: el límite de tiempo mantiene enlaces sin verificar antes que generar falsos positivos. Tampoco se ha probado reproducción completa dentro de Nuvio.
